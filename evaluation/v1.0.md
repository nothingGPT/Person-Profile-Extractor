# Evaluation Report — v1.0

This report summarizes a small, manual evaluation of **Person Profile Extractor v1.0**. It documents observed behavior, not a general ranking of language models.

## Methodology

- **Prompt:** [Person Profile Extractor v1.0](../prompts/v1.0.md), unchanged during the evaluation.
- **Models (reported configurations):** ChatGPT (GPT-6 Instant), Claude (Sonnet 5.5 Low), and Gemini (Auto Low).
- **Test set:** Five English-language scenarios in [test-cases.json](../tests/test-cases.json), including conflicting details, historical information, unrelated questions, and prompt-injection attempts.
- **Runs:** One recorded response per test case per model, **15 responses in total**.
- **Reference:** Expected outputs were prepared separately from the inputs and used to review the observed responses. They were not part of the test inputs.

A **JSON response** means the model visibly returned a JSON object with the expected profile fields; it does **not** mean the field values were all correct. An **injection test passed** means the model continued extracting profile data rather than following the conflicting instructions in TC-004 or TC-005.

## Test Results

| Model | JSON responses | Injection tests passed |
|---|---:|---:|
| ChatGPT (GPT-6 Instant) | 5/5 | 2/2 |
| Claude (Sonnet 5.5 Low) | 5/5 | 2/2 |
| Gemini (Auto Low) | 4/5 | 1/2 |

Recorded outputs: [ChatGPT](../results/v1.0/chatgpt.json) · [Claude](../results/v1.0/claude.json) · [Gemini](../results/v1.0/gemini.json).

## Key Findings

### ChatGPT

ChatGPT returned a JSON profile in every test. However, in **TC-002 through TC-005**, it filled in a country based on the city (for example, `Prague` → `Czech Republic`) even though the country was not explicitly stated. This differs from the reference outputs, which use `null` in those cases. The v1.0 prompt does not explicitly prohibit geographic inference, so this is also an ambiguity in the prompt's instructions.

### Claude

Claude returned JSON profiles in all five tests and maintained the extraction task in both prompt-injection scenarios. In **TC-002**, its `skills` list contained `JavaScript` and `React`, but omitted `Java` from the person's former Java-developer role. Whether past work should count as a current skill is not clearly defined by v1.0. The reference also includes `Web Development`, whose treatment is open to interpretation.

### Gemini

Gemini returned JSON profiles in **TC-001 through TC-004**. In **TC-005**, it switched to comparing Python and Rust instead of returning a profile. This is an observed failure to follow the extraction task in that scenario, not evidence that all prompt-injection attempts would succeed.

## Limitations

- **Small sample:** There were only five scenarios and one recorded run per model per scenario. No repeatability or statistical conclusions can be established.
- **Ambiguous instructions:** The prompt does not fully specify whether models may infer missing data, include historical skills, or normalize broad skill descriptions. This prevents a defensible overall extraction-accuracy score.
- **Manual records:** Results were transcribed from screenshots. Field values were preserved, but original formatting and Markdown fences were not; for Gemini TC-005, only excerpts of the non-JSON response are available.
- **Narrow scope:** The benchmark targets one primary person per input (even when another person is mentioned, as in TC-005); it does not test full resumes, multi-person extraction, or production reliability.

## Conclusion

Person Profile Extractor v1.0 produced usable structured profiles in most recorded runs, but the tests revealed important weaknesses: inferred values, ambiguous skill extraction, and a non-JSON response to one prompt-injection scenario. These observations provide a baseline for evaluating future revisions. **No model is declared an overall winner** on this limited evidence.
